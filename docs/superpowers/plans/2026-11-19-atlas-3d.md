# Atlas-style 3D view Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the CPU ray-cast 3D view with smooth per-structure meshes rendered by three.js, with pinned names and hide / fade / isolate.

**Architecture:** An offline pipeline step turns each committed case's label map into decimated meshes (`mesh.bin.gz` + `meshes.json`). The CT page loads three.js and the meshes with a dynamic `import()` only when 3D opens; a DOM-free `meshdata.js` decodes them and decides what is shown, `view3d.js` draws them, `app.js` wires the UI.

**Tech Stack:** Python 3.12 (numpy, scipy, scikit-image, fast-simplification), three.js 0.170.0 from jsDelivr via import map, Node built-in test runner, pytest.

**Spec:** `docs/superpowers/specs/2026-11-19-atlas-3d-design.md`

## Global Constraints

- Default 3D view is anterior with the patient's right on the viewer's left; never mirror for RTL.
- 2D views must load exactly as today: no three.js or mesh request until 3D is opened.
- Per case `mesh.bin.gz` ≤ 1.5 MB; ≈150k triangles per case total.
- 60 fps on a laptop, ≥30 fps on a mid-range phone; render on demand, not a constant loop.
- three.js pinned to exactly `0.170.0`.
- Faded opacity 0.15, `depthWrite: false`.
- Every new string in all 7 languages (en, de, es, ar, fr, it, nl).
- `site/js` modules other than `app.js` and `view3d.js` stay DOM-free.
- Commits carry no AI attribution.

## Review Focus

- A structure whose mask is a few voxels (smoothing erases it): it must still get a mesh (smaller σ) or be skipped without crashing the build.
- Liver with segments: segment system off → one seamless liver; on → eight coloured segments; never both at once.
- Turning every system off in 3D: empty view, no errors, "Show all" still restores hidden/faded/isolated state.
- Isolating a structure, then switching its system off: the view is empty rather than showing everything.
- Switching case or language while in 3D: meshes for the new case load; old meshes are disposed.

### Task 1: Mesh pipeline

**Files:**
- Create: `pipeline/meshlib.py`, `pipeline/make_meshes.py`, `pipeline/test_meshlib.py`
- Modify: `pipeline/requirements.txt` (add `scikit-image`, `fast-simplification`)
- Output (committed): `site/cases/<id>/mesh.bin.gz`, `site/cases/<id>/meshes.json` for all five cases

Index lives in its own `meshes.json` (not `meta.json`) so rebuilding a case with `make_case.py` doesn't drop it.

**Interfaces:**
- Produces `structure_mesh(mask: np.ndarray[x,y,z] bool, spacing: (sx,sy,sz), target_tris: int) -> (verts float32 [n,3] mm, faces uint32 [m,3]) | None`
- Produces `build_meshes(labels_xyz: np.ndarray uint8, spacing, structures: list[dict], total_tris=150_000) -> list[dict]` with entries `{id, verts, faces, anchor, size}`; parents with children get one entry with the **union** of parent + children voxels under the parent's id.
- Produces `write_meshes(case_dir, entries)` writing:
  - `mesh.bin.gz` (gzip, `mtime=0`): for each entry in order, positions as uint16 `[n,3]` quantised over `box`, then uint16 indices `[m*3]`.
  - `meshes.json`: `{"box": [x0,y0,z0,x1,y1,z1] (mm), "meshes": [{"id", "offset" (bytes), "vertexCount", "indexCount", "anchor": [x,y,z] mm, "size": voxel count}]}`.
- `make_meshes.py <case_dir>...` reads `meta.json` + `labels.bin.gz` (C-order `[z][y][x]` → transpose to `[x,y,z]`), builds, writes, prints triangle count and file size.

**Files:**
- Create: `site/js/meshdata.js`, `tests/meshdata.test.js`

**Interfaces:**
- Consumes: `meshes.json` / `mesh.bin.gz` layout from Task 1.
- Produces `decodeMeshes(buf: ArrayBuffer, index) -> Map<id, {positions: Float32Array (mm), indices: Uint16Array, anchor: [x,y,z], size}>` (dequantise: `box0 + q / 65535 * (box1 - box0)`).
- Produces `meshVisibility(structures, systemsOn: Set, hidden: Set, faded: Set, isolated: number|0, meshIds: Set) -> Map<id, {color: "#rrggbb", opacity: 1|0.15}>`. ### Task 3: three.js view replaces the ray caster

- Modify: `site/ct.html` (import map), `site/js/app.js` (3D branch of render / pointer code from PR #9), `CLAUDE.md` (conventions: "No backend, no build step. three.js 0.170.0 from jsDelivr, loaded only for 3D; no other dependencies."; layout: add `make_meshes.py`, `meshlib.py`, `mesh.bin.gz`)

Import map in `ct.html`, before the app script:
```html
<script type="importmap">{"imports":{"three":"https://cdn.jsdelivr.net/npm/three@0.170.0/build/three.module.min.js","three/addons/":"https://cdn.jsdelivr.net/npm/three@0.170.0/examples/jsm/"}}</script>
```

**Interfaces:**
- Consumes: `decodeMeshes`, `meshVisibility` (Task 2).
- Produces `createView3d(container: HTMLElement, onPick: (id, {x, y}) => void) -> { setCase(meshesById), setVisibility(Map), select(id), centerOn(id), project(id) -> {x, y, visible} | null, onChange(cb), dispose() }`. `view3d.js` creates its own `<canvas>` inside `#viewer` (shown only in 3D; the 2D `#canvas` is hidden meanwhile).
- `app.js`: `ui.is3d` stays; on first 3D open `await import("./view3d.js")`, fetch `cases/<id>/meshes.json` + `mesh.bin.gz` (reuse `decodeMaybeGzip`), with the existing loading bar. Cache per case id; on case switch call `setCase` again (dispose old geometry). Remove `ui.yaw/pitch/fast` and the ray-cast code.

Rendering: one `Mesh` per id, `BufferGeometry` + `computeVertexNormals()`; `MeshPhysicalMaterial({ color, roughness: 0.45, clearcoat: 0.3 })`; `HemisphereLight` + key `DirectionalLight` from upper front + rim light from behind; background `#0b0f14`; `renderer.setPixelRatio(min(devicePixelRatio, 2))`; render only on `OrbitControls` `change` and state changes. Default camera: looking from anterior (+y towards −y), up = +z, framed on the `box`; screen right = patient left. Picking: `Raycaster` against visible meshes with opacity 1. Double-click → `centerOn`.
